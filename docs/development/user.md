# 用户机制说明

本文说明这四项值的关系：
1. 构建时的用户名
2. 运行时的用户名
3. 构建时的uid/gid
4. 运行时的uid/gid

首先，权限只取决于UID和GID，和用户名无关，这两项是分开设置的。

## 用户名

本开发容器会在构建时创建一个默认用户`dev`：

```json
"build": {
    "args": {
        "USERNAME": "dev"
    }
}
```

该用户名不太适合做成动态的，因为容器在启动的时候，用户需要通过下面两项配置指定使用容器内的什么用户来执行命令

```json
"containerUser": "dev",
"remoteUser": "dev",
```

这需要保证启动时和构建时必须使用相同的用户名。所以这三个值虽然可以改，但是必须保持一致，所以这里就不方便使用环境变量，因为启动时和构建时环境不一样。

## 权限

由于 devcontainer 配置了

```json
"updateRemoteUserUID": true,
```

这让 devcontainer cli 在创建容器的时候，会用宿主机用户的UID和GID替换掉容器内的UID和GID，这样做的好处是，运行时开发容器内做的改动，在退出开发容器后仍然可以在宿主机继续编辑，就不会有权限问题。

因为这个替换机制的存在，所以：
1. 构建时用户用的权限是无所谓的。
2. 不建议直接使用docker启动容器，应该用 devcontainer 命令行启动容器
